# レンダリング結果の見かた

PDFは一度で決まらない。**必ず「出す → 調べる → 見る → 直す」を回す。**
ここはその手順と、何を見るかの一覧。実際に踏んで初めて気づいたものを並べてある。

## 手順

1. **機械で調べる** — `qtpdf check <pdf>`
   紙の外へのはみ出し、ほぼ空のページ、豆腐、埋め込みフォントを見る。
   ここで出たものは確実に不具合なので、まず直す。
2. **目で見る** — `qtpdf probe <pdf> --pages 1,5,9` でPNGを書き出し、Read で開く。
   機械では判定できないものはここでしか見つからない。
3. **直す** → 1に戻る。所見が消えるまで繰り返す。

**`check` が黙っていても「問題なし」ではない。** 機械で拾えるのは座標の異常だけで、
「表が潰れて読めない」「図が本文と噛み合っていない」は座標上は正常に見える。
2 を飛ばさないこと。

## 機械では拾えないもの(目で見る)

見るページの選び方: **表がある / 図がある / 章の変わり目 / 最終ページ**。
全ページ見る必要はないが、この4種類は必ず含める。

- **表が版面からはみ出していないか。** 列が多い表は右へあふれる。
- **表のセルの中で、コードが隣の列に重なっていないか。** 識別子は折り返せない。
- **表がページをまたぐとき、カラム名が再表示されているか。**
- **図が大きすぎ / 小さすぎないか。** Mermaid は自然サイズが巨大なことがある。
- **図の中の日本語が豆腐になっていないか。** 図はテキスト抽出できないので
  `check` の豆腐判定にかからない。**目で見るしかない。**
- **図表番号が飛んでいないか。** キャプションのない図表にも番号は付くはず。
- **見出しの番号が二重になっていないか**(「1 1. 概要」)。原稿の手書き番号が原因。
- **目次と本文の切れ目がついているか。**
- **章が新しいページから始まっているか。**
- **コードブロックの配色が意図どおりか。** 暗いテーマなら下地も暗いか。
- **ページ番号・ヘッダの内容が正しいか。** 章名が追従しているか。

## 別のエージェントに見てもらう

自分で出したものを自分で見ると、見たいものが見えてしまう。
**ページ数が多いとき、または見た目を詰める段階では、レビューを別のエージェントに渡す。**

渡し方:

- PNG の**パスを渡し、エージェント自身に Read で開かせる**。所見を渡さない。
  こちらの見立てを伝えると、それを裏付ける方向に引っ張られる。
- 「崩れていないか」ではなく、**上の一覧を渡して1項目ずつ確認させる**。
- 出させるのは「ページ番号 + 何がおかしいか + どう直すべきか」の3点。
  「概ね良い」は要らない。
- 直したあと、**同じ観点でもう一度見てもらう**。直した箇所が別の場所を壊すことがある
  (表の列幅を変えたら別の表があふれた、など実際に起きた)。

## 直す先の見当

| 見えているもの | たいてい直す場所 |
| --- | --- |
| 表が右へあふれる / 列幅が変 | `filters/numbering.lua` の列幅計算 |
| 表がページをまたげず潰れる | `base.typ` の figure の `breakable` |
| 図が巨大 / はみ出す | `filters/fit-images.lua` |
| 図表番号が付かない | `filters/numbering.lua` の float 判定 |
| 見出し番号が二重 | `--strip-numbers` を付ける |
| 章が改頁しない | `filters/pagebreaks.lua` |
| フォントが効かない | `_quarto-<design>.yml` の `mainfont` |
| コードの色が変わらない | `--code-theme` と `syntax-highlighting: none` |

直す前に `references/pitfalls.md` を読むこと。同じ問題を一度は踏んでいる。
