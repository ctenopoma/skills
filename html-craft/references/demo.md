# demo モード: 説明用シミュレータ/デモの設計

雛形: `python scripts/new_page.py demo 出力.html --title "..."`
(assets/page.css がインライン展開される)

口頭やグラフ数枚で説明していた「原理・挙動」を、**パラメータを動かすと絵が変わる**
デモに置き換える。提案・レビュー・教育で「触ってもらう」のが目的。

## 構造は3層に分ける

```js
function model(params) { ... }   // ① モデル: パラメータ → 計算結果(純粋関数)
function render() { ... }        // ② 描画: 計算結果 → SVG/DOM
// ③ 配線: input イベント → render()
```

- **model は純粋関数にする**(DOMに触らない)。見せたい原理はここに集約され、
  レビューもしやすい
- render は「状態から毎回全部描き直す」。差分更新はしない
- スライダの `input` イベントで即時再描画。計算が重い場合だけ
  `requestAnimationFrame` でスロットリングする

## コントロールの作法

- スライダ(`input[type=range]`)には**現在値の数字表示**(`.value-readout`)を必ず付ける
- 意味のある初期値にし、「リセット」ボタンを付ける
- パラメータは3個まで。それ以上は「詳細設定」に畳むか、プリセットボタン
  (`典型例A` `極端な例B` など)に置き換える。プリセットは説明の台本になる

## 見せ方

- 図は SVG 直書き(dashboard.md のグラフの型を流用)。アニメーションさせたい場合は
  CSS transition(`transition: cx .2s` など)を図形に付けるだけでも十分効く
- 図の下に `.caption` で「いま何が起きているか」を書く。可能なら
  パラメータに応じて説明文も変える(`k が大きいほど〜` を実値で言い直す)
- 「この図の見方」カードを1枚添える。初見の人はどこを見ればいいか分からない

## 精度に関する注意

デモは**傾向を伝える道具**であり、シミュレーション結果の正確さを保証するものではない。
簡略化したモデルを使う場合は、ページ内に「簡略化している点」を明記する
(数値を信じ込まれる事故を防ぐ)。
