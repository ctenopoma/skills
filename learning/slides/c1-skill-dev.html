本格スキル開発
html-craft を触りながら学ぶ

このリポジトリの html-craft(スライド / ダッシュボード / デモを 自己完結HTMLで作るスキル)を題材に、
使う → 中身を読む → 改造する → 自分のスキルを設計するまで手を動かす。

→ キーで次へ / ← で戻る

準備: スキルが入っていることを確認

html-craft はこのリポジトリ直下にあるので、clone 済みなら追加作業は不要。

# フォルダがあることを確認
ls ~/.claude/skills/html-craft
  1. Claude Code を再起動する(スキルは起動時に読み込まれる)
  2. 作業用の空フォルダを1つ作って、そこで Claude Code を開くと成果物が散らからない

PDF 書き出し(後で試す)は Microsoft Edge を使う。Windows なら標準搭載なので準備不要。

この教材のレベルAで学んだこと(Skill=手順書、MCP=道具箱、連携=名前を書くだけ)を
5枚のスライドにして。ファイル名は level-a-recap.html

確認ポイント(できたら1つずつチェック):

  • HTML 1ファイルだけが生成されたか(assets 等の別ファイルがないか)

中身を読む①: SKILL.md — なぜ言い方だけで切り替わったか

code ~/.claude/skills/html-craft/SKILL.md   # エディタで開く

探しながら読む(答え合わせは次ページ):

  1. description に、さっき自分が使った言い回し(「スライド作って」等)が入っているか?
  2. 3モードの判定はどこでやっている?(description か、本文か)
  3. 「自己完結」を守らせている文はどれ?

中身を読む①: 答え合わせ

  • 発動は description、分岐は本文。description には3モード全部の トリガー語が並び、モード判定は本文冒頭の表(意図 → モード → 必読 references)で行う。 ユーザーから見て「HTMLの成果物が欲しい」という同じ場面だから1スキルに統合している
  • 自己完結は「ルール」節の1行(CDN・外部フォント・fetch 禁止)。 ハンズオン1で grep が 0 件だったのはこの1行の効果
レベルAで学んだ「description が発動を決める」はそのまま。本格スキルで増えたのは モード分岐と、モードごとに読む references の振り分け。

中身を読む②: references と scripts

references — ハンズオン1の成果物と見比べる:

  • references/slides.md を開き、「使える部品」の表と、 自分の level-a-recap.html に使われている部品(.note / .flow / .chip 等)を突き合わせる
  • 背景説明ではなくパターン集(型+ルール)として書かれていることを確認

scripts — 実行して仕組みを見る:

python ~/.claude/skills/html-craft/scripts/new_page.py slides test.html --title "テスト"
grep -c "<style>" test.html   # CSS がインライン展開されている
  • to_pdf.py のコメントを読む: Edge が起動済みインスタンスに処理を委譲する・ 数秒遅れて書き出す、というクセの回避策がコードに焼かれていることを確認

改造ハンズオン: 自分の定番部品を references に足す

お題: 「2カラム比較」レイアウトを部品として追加し、スキルに使わせる。

  1. references/slides.md の「使える部品」表の下に追記: 
    ## 追加部品: 2カラム比較

対比(before/after、案A/案B)はこの型を使う:

<div style="display:grid; grid-template-columns:1fr 1fr; gap:16px">
  <div class="note"><strong>案A</strong><br>...</div>
  <div class="note"><strong>案B</strong><br>...</div>
</div>
  2. Claude Code を再起動
  3. 試す: 
    STDIOとHTTPの比較スライドを1枚作って
  4. 確認: 2カラムの型が使われたか。使われなければ「対比は2カラム部品で」と 指示に足してみる → SKILL.md 側への誘導文が必要かを考える(これが手順書の改善サイクル)

ふりかえり: いま触った構造の設計原則

置き場所置くもの(判断基準)ハンズオンで見た実物
SKILL.md毎回必要な判断と手順の骨格モード判定表・自己完結ルール
references/状況別の詳細知識。パターン集として書くslides.md の部品表(+自分の追加部品)
assets/実証済みの部品(ゼロから書かせない)deck.css(この教材の紙芝居と同じもの)
scripts/毎回同じで、LLM にやらせると不安定な処理new_page.py / to_pdf.py(Edge のクセ対策入り)
本格スキルの設計=「どの知識を・いつ読ませるか」「どの処理を・コードに固めるか」の設計。 レベルAの段階的開示のフルサイズ版。
