題材の選び方: ツール導入型スキル

狙い目は「既にやっている業務」×「便利だと知っているが、導入・学習コストで使えていないやり方」の交点。 面倒な部分をスキルに吸収させ、良いやり方だけを手に入れる。

実例置き換える業務吸収した面倒
quarto-typst-pdf技術文書のPDF作成Quarto/Typst の環境構築・記法・調整
html-craftスライド作成 / データ共有 /
口頭での原理説明		HTML/CSS/JS の設計、自己完結化、PDF化
html-craft の発想: PowerPoint・Excelスクショ・口頭説明を、ブラウザで直接開ける 自己完結HTML 1ファイルに置き換える。変換ツールを介さず LLM が直接 デザインするので自由度が高い。この教材の紙芝居がそのまま実績サンプル。

html-craft の全体像: 1スキル3モード

ユーザーの意図モード置き換える業務
発表・報告・説明資料(ページをめくる)slidesPowerPoint
データを眺める・共有する(フィルタ・表・グラフ)dashboardExcel+スクショ共有
原理・挙動を触って見せる(パラメータで変わる)demo口頭+静止画の説明

共通の要件(コードより先に文章で固めた)

  • HTML 1ファイルで完結。CDN・外部フォント・fetch 禁止(オフラインで開ける)
  • ブラウザ確認を経てから完成とする。PDF化もできる

この要件がそのまま SKILL.md の「ルール」節になる。要件 → ルール、の直結。

設計の本体: 知識と処理の「置き場所」

html-craft/ ├── SKILL.md 常に必要な判断(モード判定)と手順の骨格 ├── references/ │ ├── design.md 共通デザイン原則(全モード必読) │ ├── slides.md ┐ │ ├── dashboard.md ├ モード別パターン集(必要時だけ読む) │ └── demo.md ┘ ├── assets/ │ ├── deck.css / deck.js スライド用フレームワーク(実証済み) │ └── page.css ダッシュボード/デモ用ベース └── scripts/ ├── new_page.py 雛形生成(assets をインライン展開) └── to_pdf.py PDF化(Edge ヘッドレス印刷)
本格スキルの設計とは「どの知識を・いつ読ませるか」「どの処理を・コードに固めるか」の設計。 レベルAで学んだ段階的開示の、フルサイズ版。

置き場所の判断基準

置き場所判断基準
SKILL.md毎回必要な判断と手順の骨格だけ。長くしない
references/状況によって要る詳細知識。パターン集として書く(構成の型、悪い例→良い例、使える部品一覧)。背景説明より判断基準
assets/実績のある部品を転用する。html-craft の CSS/JS は、この教材の紙芝居で実際に使って磨いたものをそのまま採用。ゼロから書かせない
scripts/毎回同じで、LLM にやらせると遅い・不安定な処理だけ。デザイン判断はスクリプト化しない

description の設計: 統合スキルの発動

3モードを1スキルに統合したので、description に全モードのトリガー語を入れる。

description: スライド・ダッシュボード・インタラクティブデモを、
  ブラウザで直接開ける自己完結HTML 1ファイルとして作る。
  ユーザーが「スライド作って」「発表資料」「紙芝居」「ダッシュボード」
  「データを見られるページ」「デモ/シミュレータ作って」
  「HTMLで資料化して」などと言ったときに使う。...
発動は description、分岐は本文。モードの判定は SKILL.md 冒頭の表 (意図 → モード → 必読 references)で行う。1スキルに統合したのは、 ユーザーから見て「HTMLの成果物が欲しい」という同じ場面だから。

scripts 開発の実話: Edge の非同期書き出し

to_pdf.py(Edge ヘッドレス印刷、追加インストール不要)は、素朴に書くと動かないことがある。

  1. 既定プロファイルだと、起動済みの Edge に処理が委譲されてすぐ制御が返る
    → --user-data-dir で専用プロファイルを指定して回避
  2. それでも Edge はプロセス終了の数秒後に PDF を書き出すことがある
    → ファイル出現をポーリングして待つ
道具のクセは一度だけ解いて、コードに焼く。LLM に毎回この回避策を 思い出させるのではなく、スクリプトに封じ込める。これが scripts/ の存在理由。

マルチエージェント: 大型デッキの分担執筆

15枚を超えるスライドは分担が速い(手順は references/slides.md に収録)。

親アウトライン確定
ユーザーと合意
→章ごとに指示
(並列)
サブ×Nスライド断片を執筆
<section class="slide">
→結合
親一貫性の担保
用語・デザイン・粒度
  • アウトラインの確定は分担しない(輪郭は親が握る)
  • サブエージェントは文脈を共有しない。書式ルール(1枚1メッセージ、 タイトルは要約文)を毎回の指示に含める
  • 重複削除・リズム調整・枚数の刈り込みは親の最終責任

ハンズオン: html-craft を使う

スキルは既にこのリポジトリ(= ~/.claude/skills/html-craft/)にある。再起動して試す。

モード話しかけ方の例
slides「レベルAで学んだことを5枚のスライドにして」
dashboard「plot-mcp の sample/timeseries.csv をダッシュボードにして。センサー切替できるように」
demo「移動平均の窓幅で滑らかさが変わるデモを作って」
PDF化「いまのスライドを PDF にして」→ scripts/to_pdf.py が呼ばれる

どのモードでも、完成した HTML をブラウザで開いて 「1ファイルで動くこと」「外部通信がないこと」を確認する。

発展課題: レベルA・Bの部品と組み合わせる

  1. 調査報告パイプライン: paper-library-mcp で検索 → 文献ごとに サブエージェントで要約 → 比較統合 → html-craft (slides) で報告資料に
  2. 解析報告パイプライン: plot-mcp で図を量産 → base64 で dashboard に埋め込み
  3. 自分の業務からツール導入型スキルの題材をひとつ選ぶ。 作り始める前に「置き場所マップ」(SKILL.md / references / assets / scripts に 何を置くか)を埋める
