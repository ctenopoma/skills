この章で学ぶこと

  1. 入力がバイナリ (PDF)
    pypdf でテキスト抽出してから SQLite にインデックスする。 B-1(出力が画像)と対になる「入力がテキスト以外」のパターン
  2. tools に加えて resources を使う
    MCP の2つ目の主要機能。「操作」と「読み物データ」を分ける

ダウンロード済み PDF の山をどう活用するか — プロキシ環境の実務でそのまま役立つ題材でもある。

ハンズオン: 自分で作る(1/2) — 配管は写し、抽出を書く

my-papers/server.py を新規作成。冒頭の LIB_DIR / DB_PATH 定義と _db(SQLite 接続)・reindex(フォルダ走査)は定型の配管なので、 完成例 learning/level-b/paper-library-mcp/server.py からコピーしてよい。 バイナリ→テキスト変換の本体 _extract は写経する:

my-papers/server.py(抜粋) 
from pypdf import PdfReader

def _extract(pdf_path: Path) -> tuple[str, int, str]:
    """PDF からタイトル・ページ数・本文テキストを取り出す。"""
    reader = PdfReader(pdf_path)
    text = "\n".join((page.extract_text() or "") for page in reader.pages)
    title = ""
    if reader.metadata and reader.metadata.title:
        title = str(reader.metadata.title).strip()
    if not title:  # メタデータになければ本文の最初の行で代用
        title = next((ln.strip() for ln in text.splitlines() if ln.strip()),
                     pdf_path.stem)[:120]
    return title, len(reader.pages), text

バイナリ → テキストの変換はこの関数だけ。あとはレベルAと同じ世界(文字列と SQLite)。

ハンズオン: 自分で作る(2/2) — 検索とリソースを仕様から書く

ここはコードを見ずに、仕様だけで実装する。

作るもの仕様
search_papers(query)
(tool)		 タイトルまたは本文の部分一致(SQL の LIKE)で検索。ヒットごとに 「ファイル名 | タイトル+ヒット箇所の前後80字」を返す。0件なら「一致なし」。 結果の最後に「全文はリソース paper://<ファイル名> で」と誘導文を入れる
read_paper(filename)
(resource)		 @mcp.resource("paper://{filename}") で本文テキスト全文を返す。 未登録のファイル名なら「reindex 済みか確認」と返す

ヒント(詰まったときだけ):

  • リソースはデコレータが違うだけ。{filename} 部分がそのまま引数になる
  • スニペットは text.lower().find(query.lower()) の位置の前後を切り出す
  • 誘導文が「検索 → 全文」の段階的開示を作る(Skill の設計と同じ発想)

動かす

pip install "mcp[cli]" pypdf

# ライブラリフォルダを作り、手持ちの PDF を数本入れる
mkdir ~/paper-library

claude mcp add paper-library -- python (my-papers/server.py の絶対パス)

場所を変えたいときは環境変数 PAPER_LIBRARY_DIR を設定する。 日本語 PDF も pypdf で抽出できる(スキャン画像だけの PDF はテキストが取れないので対象外)。

動作確認: 検索 → 全文 → 要約

  1. インデックス: 
    文献ライブラリをインデックスして
    → reindex → 「N 件の PDF をインデックスした」
  2. 検索: 
    ◯◯について書いてある文献ある?
    → search_papers → ファイル名+タイトル+ヒット箇所の前後
  3. 全文を読ませて要約: 
    その1本目、要約して
    → Claude が paper://ファイル名.pdf リソースを読んで要約する。 @paper-library:paper://ファイル名.pdf と自分で指定してもよい

改造課題

  1. サブフォルダも走査する(glob("**/*.pdf"))
  2. 差分インデックス(追加されたファイルだけ処理)にする
  3. SQLite の FTS5 を使って検索を高速化し、スコア順に並べる
  4. 本文から著者・発行年の抽出を足し、search_papers に年での絞り込みを付ける

他ツールでの利用と、まとめ

  • --http 起動で他クライアントからも使える(レベルAと同じ)
  • resources への対応度はクライアント差がある。リソース相当を返す get_paper_text(filename) ツールを併設しておくと互換性が上がる (tools はほぼ全クライアントが対応)

レベルBで学んだこと

  • 出力が画像でも入力が PDF でも、@mcp.tool() + docstring の作りは不変
  • バイナリはサーバ側でテキスト/画像コンテンツに変換して LLM に渡す
  • tools(操作)と resources(読み物)の分担。段階的開示はデータ設計にも効く
