レベルAとの違い: コンテンツ型

MCP のツールが返せるのはテキストだけではない。

型中身例
TextContent文字列レベルAの全ツール
ImageContentbase64 の画像 + MIME タイプこの章のグラフ
EmbeddedResourceリソース参照B-2 で扱う
クライアント側の LLM は返ってきた画像を「見る」ことができる。つまり 「グラフを描かせて、そのグラフを見て考察させる」が1往復でできる。 これが画像を返せることの実用的な意味。

データの流れ

CSV ファイル手元のデータ
→pandas で読む
matplotlibAgg バックエンドで描画
(画面いらず)
→PNG バイト列
Image 型で returnSDK が base64 化して
ImageContent に包む
→
Claude が画像を見る

base64 化や MIME タイプの付与は SDK がやってくれる。 自分で書くのは「PNG のバイト列を Image 型に入れて返す」ところまで。

コードの骨格: Image を返す

server.py(抜粋) 
from mcp.server.fastmcp import FastMCP, Image
import matplotlib
matplotlib.use("Agg")  # 画面を持たない環境用

def _fig_to_image(fig) -> Image:
    buf = io.BytesIO()
    fig.savefig(buf, format="png", dpi=110, bbox_inches="tight")
    plt.close(fig)
    return Image(data=buf.getvalue(), format="png")

@mcp.tool()
def plot_csv(csv_path: str, x: str, y: str, kind: str = "line") -> Image:

    時系列や2変数の関係を見たいときに使う。..."""
    df = pd.read_csv(csv_path)
    fig, ax = plt.subplots(figsize=(7, 4))
    ...
    return _fig_to_image(fig)

@mcp.tool() + docstring という作りはレベルAと完全に同じ。 変わったのは戻り値の型だけ。

ツールは3つ — docstring で順番を誘導

ツール返すものdocstring での役割づけ
describe_csvテキスト「グラフを描く前に、どんな列があるかの下見に使う」
plot_csv画像「時系列や2変数の関係を見たいときに」
histogram画像「分布の形や外れ値の確認に」
テキストと画像のツールが同居できる。そして docstring に「使う場面」を書いておくと、 Claude は自然に describe で下見 → plot / histogram で描画 の順で使う。 レベルAで学んだ「docstring が LLM へのインターフェース」の実践形。

  1. 下見: 
    learning/level-b/plot-mcp/sample/timeseries.csv ってどんなデータ?

  2. 描画: 
    センサー2つの推移をグラフにして

  3. 考察まで: 
    sensor_b の分布は?外れ値ある?

改造課題

  1. kind に "box"(箱ひげ図)を追加する
  2. 日本語の列名でラベルが文字化けする場合の対処(matplotlib のフォント設定)を入れる
  3. save_plot(csv_path, x, y, out_path) を追加し、画像で返すだけでなく ファイルにも保存できるようにする(レポートに貼る用)
  4. 「describe → 分布 → 関係」の順で下見する手順を Skill 化する
    • レベルA Step 3 の応用。道具が増えたら手順書も書ける

他ツールでの利用と、まとめ

  • --http で起動すれば OpenWebUI 等からも使える(レベルAと同じ)
  • 画像コンテンツの表示はクライアントの対応状況に依存する (Claude Code / Claude Desktop は表示できる)

この章で学んだこと

  • ツールの戻り値は Image 型にするだけで画像になる(base64 化は SDK 任せ)
  • LLM は返った画像を見て考察できる — 描画+解釈が1往復
  • テキスト・画像のツールは同居でき、docstring で使う順番を誘導できる
