レベルAとの違い: コンテンツ型

MCP のツールが返せるのはテキストだけではない。

型中身例
TextContent文字列レベルAの全ツール
ImageContentbase64 の画像 + MIME タイプこの章のグラフ
EmbeddedResourceリソース参照B-2 で扱う
クライアント側の LLM は返ってきた画像を「見る」ことができる。つまり 「グラフを描かせて、そのグラフを見て考察させる」が1往復でできる。 これが画像を返せることの実用的な意味。

データの流れ

CSV ファイル手元のデータ
→pandas で読む
matplotlibAgg バックエンドで描画
(画面いらず)
→PNG バイト列
Image 型で returnSDK が base64 化して
ImageContent に包む
→
Claude が画像を見る

base64 化や MIME タイプの付与は SDK がやってくれる。 自分で書くのは「PNG のバイト列を Image 型に入れて返す」ところまで。

ハンズオン: 自分で作る(1/2) — 骨格と Image 変換

my-plot/server.py を新規作成し、骨格を写経する。 Image 変換と「下見」ツールまでは提供:

my-plot/server.py 
import io, sys
import matplotlib
matplotlib.use("Agg")  # 画面を持たない環境用
import matplotlib.pyplot as plt
import pandas as pd
from mcp.server.fastmcp import FastMCP, Image

mcp = FastMCP("plot")

def _fig_to_image(fig) -> Image:
    buf = io.BytesIO()
    fig.savefig(buf, format="png", dpi=110, bbox_inches="tight")
    plt.close(fig)
    return Image(data=buf.getvalue(), format="png")

@mcp.tool()
def describe_csv(csv_path: str) -> str:
    """CSV の概要(行数・列名・基本統計量)を返す。グラフを描く前の下見に使う。"""
    df = pd.read_csv(csv_path)
    return f"行数: {len(df)}\n列: {', '.join(df.columns)}\n\n{df.describe().to_string()}"

if __name__ == "__main__":
    mcp.run()

@mcp.tool() + docstring はレベルAと完全に同じ。新要素は 「Figure → PNG バイト列 → Image 型で return」の3行だけ。

ハンズオン: 自分で作る(2/2) — 画像ツール2本を仕様から書く

ここからはコードを見ずに、仕様だけで実装する。 Figure を作って _fig_to_image(fig) を返すだけ。

ツール仕様
plot_csv(csv_path, x, y, kind="line") x 列・y 列でグラフを描いて画像で返す。kind は "line" / "scatter" / "bar" の3種
histogram(csv_path, column, bins=20) 1列のヒストグラムを画像で返す(ax.hist)。欠損は dropna() してから

docstring には「いつ使うか」も書く(例: histogram は「分布の形や外れ値の確認に使う」)。

答え合わせ

動いたら完成例 learning/level-b/plot-mcp/server.py と自分のコードを見比べる。

  • y の複数列対応: 完成例はカンマ区切りで複数系列を受け、 ax.legend() で凡例を付けている。「センサー2つの推移」が 一発で描けるのはこの設計のおかげ
  • 後始末: _fig_to_image の plt.close(fig)。 サーバは長時間生きるので、閉じ忘れると Figure が溜まり続ける
  • docstring の役割づけ: describe は「下見に使う」、histogram は 「外れ値の確認に」— この一言で Claude が describe → 描画の順で自然に使う。 自分の docstring と見比べる

この章で学んだこと

  • ツールの戻り値は Image 型にするだけで画像になる(base64 化は SDK 任せ)
  • LLM は返った画像を見て考察できる — 描画+解釈が1往復
  • テキスト・画像のツールは同居でき、docstring で使う順番を誘導できる
