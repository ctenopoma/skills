# eda-workflow: 探索的データ解析の型

データを受け取ったときに毎回同じ品質で「下見」を終わらせるための手順書。
計算と描画は MCP ツールに任せ、このスキルは順序と判断を担当する。

## 手順

0. **前提確認**: データのパス、分析の目的、目的変数(あれば)を確認する。
   目的が示されなければ「全体把握」モードとして進める
1. **読み込みと概要**: `mcp__data__load` で読み込み、行数・列・型を報告する
2. **品質チェック**: `mcp__data__profile` の結果を references/quality.md の
   チェックリストで評価する(欠損・重複・外れ値・型・表記ゆれ・リーク)。
   問題を見つけたら対処方針をユーザーに確認してから先へ進む
3. **分布を見る**: 主要な数値列を `mcp__plot__histogram`、カテゴリ列は
   data-mcp の SQL で度数集計。図の選び方は references/charts.md に従う
4. **関係を見る**: `mcp__stats__correlation` で当たりを付け、強い関係だけを
   `mcp__plot__plot_csv`(scatter)で目視確認する
5. **深掘り**(目的がある場合): references/methods.md の選定フローに従う
   - 群間の差 → `mcp__stats__compare_groups`(必要なら先に `check_normality`)
   - カテゴリ同士の関連 → `mcp__stats__test_independence`
   - 予測できそうか → `mcp__stats__quick_fit`(ベースラインの当たり付けまで)
6. **所見まとめ**: 「データ概要 / 品質上の注意 / 主要な発見(図・数値つき) /
   次の一手の提案」の4部構成で報告する。レポートとして残したいと言われたら
   html-craft(dashboard)での成果物化を提案する

## ルール

- **大きいデータをコンテキストに読み込まない**。中身の確認・集計・抽出は必ず
  data-mcp の SQL で行い、結果の要約だけを扱う
- **統計量・検定・モデル評価を暗算しない**。数値は必ず stats-mcp の結果を使う
- 発見は必ず図か数値で裏付ける。「〜のように見える」で終わらせない
- 相関・特徴量重要度から因果を断定しない
- 各ステップの所見は1〜3行で簡潔に。詳細は最後のまとめに回す
