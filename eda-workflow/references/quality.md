# データ品質チェックリスト

profile の結果をこの順で確認する。問題があれば「発見→影響→対処案」をセットで報告する。

## チェック項目

| 項目 | 見るところ | 危険信号 |
| --- | --- | --- |
| 欠損 | 列ごとの欠損数・率 | 率が高い(>20%)、特定条件に偏った欠損 |
| 重複 | `SELECT count(*) - count(DISTINCT ...)` | ID列があるのに重複、全列一致の行 |
| 外れ値 | min / max / mean の乖離 | 物理的にあり得ない値(負の年齢、9999等の欠損コード) |
| 型 | DESCRIBE の型 | 数値のはずが VARCHAR(単位・カンマ・空白混入) |
| 表記ゆれ | カテゴリの top 値 | "A" と "a"、全角半角、前後空白で別カテゴリ化 |
| 単位・スケール | 列名と値の範囲 | 列によって単位が混在(m と mm 等) |
| リーク | 目的変数と列の意味 | 目的変数の結果から作られた列(未来の情報)が説明変数にある |
| ID・定数列 | ユニーク数 | 全行ユニーク(ID)や1種類だけの列は分析から除外 |

## 対処の選択肢(勝手に決めず、方針をユーザーに確認する)

- **欠損**: 行削除(欠損が少なく無作為なら)/ 代表値補完(中央値・最頻値)/
  「欠損フラグ列」を追加(欠損自体に意味がある場合)
- **外れ値**: まず原因を調べる(入力ミスか実測か)。機械的に除外しない。
  除外・上限クリップ・対数変換は理由とセットで
- **重複**: 重複の発生理由(結合ミス・再送)を確認してから削除
- **型・表記ゆれ**: data-mcp の SQL(CAST, trim, lower 等)で正規化し、
  export で処理済みファイルを作って以降はそれを使う
